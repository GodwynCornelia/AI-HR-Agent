# Улучшение агента: этапы и критерии

Исходный коммит: f997bec080ebeb3a283ae7b95d2b0e3ecad42371, ветка HR_Agent; main не менять. Qwen3:4b, EmbeddingGemma, 4096/700, TOP_K=8, история 6 пар / 4000 символов. Старые результаты agent_dev остаются исходной диагностикой. Текущие test/holdout не используются как независимый тест. Нового final test нет.

| Симптом | Подтверждённая причина / гипотеза | Изменение | Критерий |
|---|---|---|---|
| Первый пустой поиск завершает граф | tool выставляет no_new_evidence при not new | Разделить empty/irrelevant/partial/complete/repeated/error; ограничить неуспешные попытки | Пусто → другой поиск → ответ; все пусты ограниченно завершаются |
| Новые чанки принимаются за пользу | Измеряется только число новых ID | Отдельно измерять новые тексты, доказательства и покрытые части | Бесполезные новые ID не обнуляют счётчик |
| Read не добавляет контекста | Возвращается тот же полный чанк | Читать максимум соседей ±1 по document_id/ordinal, до 4000 символов за чтение, не более 2 чтений | Недостающее условие действительно доступно; удаление/переиндексация отклоняются |
| Теряются тема и условия | topic=query, conditions=список вопросов | Компактное структурированное состояние из пользовательских сообщений; проверенные источники как referent | Замены условий и смена процедуры проверены; неизвестное не угадывается |
| Missing слишком общий | Один sufficient и список текстовых дефицитов | Части вопроса с доказательствами и типом недостающего | Следующее действие связано с конкретной частью |
| Лишний вызов после достаточности | assess → plan → answer | Детерминированное завершение после проверенного sufficient | Простая выдача без повторного решения; защиты сохранены |
| Судья завышает баллы | Та же слабая модель, калибровка не пройдена | Сохранить фактические ответы, привязку к доказательствам и разбор расхождений | Статус/цитата/LLM-балл не выдаются за успех |

Порядок: (0) исходные тесты/хеши → (1) управление поиском и короткая живая проба → (2) соседний контекст и проба → (3–4) состояние/части вопроса и компонентные проверки → (5) оптимизация перехода → (6–7) отдельные естественные и одинаково контролируемые dev-прогоны → (8) документация, Git, компактный ZIP без секретов.

На устойчивую модельную проблему — максимум две последовательные целевые итерации без нового доказательства причины. Отрицательные результаты сохраняются. Доступ, числовые проверки и итоговая валидация обязательны; платных сервисов и новых поисковых архитектур нет.
