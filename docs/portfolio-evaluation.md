# Фиксация портфолио-эксперимента

Исходная версия 68ab639 совпала с архивом аудита. Режим по умолчанию на этапе разработки — обычный dense RAG. LangGraph доступен для диагностики дополнительных поисков и чтения.

## Проверки кандидата

79 тестов пройдены. Подтверждения хранятся по частям вопроса с ключом из ID чанка и точной цитаты. Временный псевдоним E может меняться. Явное отклонение удаляет подтверждение из реестра. Заключительная проверка использует актуальные данные чанка.

Компонентная модель сформировала три запроса по дефицитам, а реальный индекс вернул тематические фрагменты. На наставнике модель повторила исходный составной вопрос. Поэтому при дополнительном поиске добавляется предмет из подготовки диалога, если он выпал из запроса.

В контролируемой пробе соседнего контекста по командировке опорный чанк оценён как недостаточный. Чтение добавило абзацы 3 и 5 того же регламента. В абзаце 3 нашлось подтверждение, что командировку согласуют руководитель команды и владелец бюджета. В объединённом контексте оценка выбрала его и правило для срочной поездки. Такой результат показывает пользу текста в контролируемом компонентном сценарии. Записи — experiments/agent_v2/portfolio_component_probes.json.

При проверке наставника на первой итерации новая оценка вернула пустой список подтверждений у обоих режимов. Вторая итерация добавляет один общий повтор выбора выдержек по упрощённой схеме при пустом структурированном результате. Результат проверки второй итерации нужен до выбора кандидата.

## Порядок финального измерения

1. Выбрать кандидата по dev и закрепить SHA. Составить 30–40 новых сценариев, проверить смысловые пересечения со старыми вопросами и закрепить обязательные факты, допустимые действия и доказательства. Указать отдельно число реплик.
2. Прогнать весь файл командой `python tools/run_with_profile.py tools/compare_agent_dev.py --frozen-final <файл>`. Скрипт проверяет SHA рабочего дерева и фиксирует хеш файла. Модель получает только реплику и собственную историю. A использует один dense поиск, B допускает до трёх поисков, двух чтений и восьми решений. Оба используют один профиль, корпус, индекс и общий путь подготовки и генерации. Прогрев и чередование режима предусмотрены.
3. Считать Recall@8 только по первой выдаче и только на вопросах с положительными подтверждениями. Отдельно измерять объединённый пул, контекст перед оценкой и выбранные цитаты. Успешное восстановление требует нового подтверждения и ответа на пропущенную часть. Задержки и технические ошибки учитывать на всех репликах.
4. Сохранить объективный пересчёт и предварительные семантические оценки с объяснениями. Для ручной проверки подготовить 6–8 пар со случайно перемешанными вариантами и раздельным ключом. Решение о режиме опирается на парные результаты и задержки.

Финальный набор и финальные метрики ещё не зафиксированы.
